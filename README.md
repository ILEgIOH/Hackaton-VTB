# ComputeCollateral

Настольное приложение для банка: оценка и **мониторинг GPU-серверов как залога по кредиту**.
Банк загружает перечень оборудования заёмщика, подключает телеметрию (агент на серверах / снимок `nvidia-smi`),
получает рыночную и ликвидационную стоимость, прогноз покрытия долга в трёх сценариях и рекомендуемый LTV —
а после выдачи кредита система **следит за серверами** (подмена карт, перегрев, потеря связи, нарушение ковенанта),
а подключаемая **нейросеть через открытый OpenAI-совместимый API** разбирает телеметрию и даёт рекомендации.

Интерфейс сделан по макетам `ComputeCollateral v5` (вход, портфель, мастер «Новая оценка», карточка сделки,
рыночные данные, уведомления).

## Запуск

```bash
python run.py              # окно приложения (если установлен pywebview) или браузер
python run.py --browser    # принудительно браузер
python run.py --reset      # пересоздать демо-данные
```

Нужен Python 3.10+. Единственная зависимость — `openpyxl` (Excel); `pywebview` — по желанию для нативного окна:
`pip install -r requirements.txt`. Откроется http://127.0.0.1:8765/ — вход **e.sokolova@bank.ru / Compute2026**.

Данные хранятся в `data/db.json` (папку можно сменить переменной `CC_DATA_DIR`).

## ИИ-наблюдатель

*Настройки → ИИ-наблюдатель.* Подойдёт любой сервис с `/chat/completions` в формате OpenAI: OpenAI, OpenRouter, Groq,
Together, а также локальные Ollama / vLLM / LM Studio (ключ не нужен для `localhost`). Либо переменные окружения
`CC_AI_BASE_URL`, `CC_AI_API_KEY`, `CC_AI_MODEL`.

Модель получает JSON-снимок сделки (температура, загрузка, наработка, совпадение серийных номеров, связь, покрытие)
и возвращает риск, замечания и рекомендации; анализ запускается кнопкой, по расписанию и в чате («Спросить ИИ»).
Важные свойства:

* **правила работают всегда** — без ИИ и при его сбое остаётся детерминированный анализ;
* **ИИ не может занизить риск**, найденный жёсткими правилами (например, подмену серийного номера);
* API-ключ хранится только на сервере и не отдаётся интерфейсу.

## Агент на серверах

```bash
python agent/agent.py --server http://HOST:8765 --token <токен из мастера> --name srv-01
python agent/agent.py ... --mock        # проверка без GPU
```

Агент раз в минуту шлёт серийные номера, температуру, загрузку и наработку (счётчик ведёт сам агент).
Сервер сверяет серийные номера с договором залога, ловит обрыв связи и сброс счётчика наработки.

## Демо

В демо-портфеле шесть сделок, телеметрия «живая» (симуляция, отключается в настройках). На вкладке сделки
**ИИ-мониторинг → Демонстрация инцидентов** можно сымитировать перегрев, подмену карты или обрыв связи
и увидеть уведомление и реакцию ИИ.

## Ограничения (честно)

* Рыночные цены, ставки аренды и сценарии падения цен — **демонстрационные допущения**, а не реальный источник данных.
  Их нужно заменить подключением к прайсам дилеров / биржам вычислений (`market.py`, `scen` в нём).
* Модель износа (наработка, температура, загрузка) эвристическая и требует калибровки на реальных сделках.
* Хранилище — JSON-файл, сессии в памяти: достаточно для настольного приложения и хакатона, не для промышленной эксплуатации.
  Сервер слушает только `127.0.0.1`; при выставлении наружу нужен TLS и полноценная аутентификация.
