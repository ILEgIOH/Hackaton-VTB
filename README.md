# ComputeCollateral

Настольное приложение для банка: оценка и **мониторинг GPU-серверов как залога по кредиту**. Сделано по документам
«ComputeCollateral v5» (макеты) и «Путь пользователя» (47 страниц: экраны, кнопки, переходы, ошибки, расчёты, роли).

Аналитик загружает перечень оборудования заёмщика, подключает телеметрию (агент на серверах / снимок `nvidia-smi`), получает
рыночную и ликвидационную стоимость, прогноз покрытия долга в трёх сценариях и рекомендуемый LTV. После выдачи кредита система
следит за серверами (подмена карт, перегрев, обрыв связи, нарушение ковенанта), а сотрудники банка принимают решения по
уведомлениям. Подключаемая **нейросеть (любой OpenAI-совместимый API)** разбирает телеметрию и подсказывает; на стоимость,
статусы и решения она не влияет — «нейросетей в расчётах нет» (ТЗ, «Данные: что откуда берётся»).

## Запуск

```bash
pip install -r requirements.txt        # без reportlab / python-docx работает всё, кроме выгрузки PDF / Word
python run.py                          # окно приложения (pywebview) или браузер: http://127.0.0.1:8765/
python run.py --browser                # принудительно браузер
python run.py --reset                  # пересоздать демо-данные
python -m unittest discover -s tests   # тесты (41)
```

## Что реализовано по ТЗ

* **Вход V01–V04:** только домен @bank.ru, 3 ошибки подряд → блокировка на 15 минут, восстановление пароля (одинаковый ответ для любой почты, повтор через 60 с), сессия 30 минут.
* **Портфель P01–P04:** сортировка колонок, фильтры, поиск по компании и серийному номеру из шапки (с 3 символов), пустые состояния.
* **Новая оценка N01–N11:** 4 шага; ИНН с контрольной суммой и защита от дубля (N02); проверка файла по строкам (13 цифр, дубли, дата, модель — N04); агент с ключом `CC-XXXX-XXXX` и письмом в ЦОД; «часть серверов молчит → продолжить без них» (N08); ошибки под полями (N10); расчёт с прогрессом и уведомлением «Оценка готова» (N11); черновик сохраняется.
* **Компания C01–C06, E01–E05, D01–D04:** обзор с графиком и ползунками (условия сохраняются в сделке), ликвидационная база LTV, «Переоценить» с «было → стало» и сохранением прежней оценки в документах, оборудование с жёлтыми/красными строками, письмо в ЦОД, документы, выгрузка заключения в **PDF и Word** с выбором разделов.
* **Уведомления U01–U08:** запрос обеспечения, выездная проверка, наблюдение (возврат в «Ждут решения» в нужную дату), «уже решено другим» (409), повторная отправка без дубля письма при сбое сети, настройки по типам и пороги (меняет только «Управление рисков»).
* **Рынок M01–M02:** разброс цен, источники цены по клику, пометка «Мало данных», пометка «данные старше 3 дней».
* **Расчёты (engine.py):** три метода (веса 0,3/0,4/0,3; при малом числе цен 0,4/0,25/0,35), доходный метод (ставка × 8760 × загрузка, −30 %/год, дисконт 22 %, 3 года), износ 0–7 %, ликвидационный дисконт 28 %, сценарии (22 / 32 / 50 % в год, ×0,85 для H100 после выхода нового поколения), аннуитет, LTV ≤ 75 %, статусы 1,25 / 1,40. Контрольные цифры макета воспроизводятся: рыночная ≈ 94,0 млн ₽, LTV 52,4 %, по ликвидационной базе 37,7 %.
* **Ошибки X01–X05:** скелетон загрузки, ошибка загрузки с «Повторить», нет доступа, сессия завершена, сбой отправки (окно не закрывается, данные сохранены).

## Подключение нейросети по API

*Настройки → «Нейросеть: подключение по API»* (доступно аналитику и управлению рисков). Два режима:
- **Claude (нативный API, рекомендуется)** — `base_url = https://api.anthropic.com`, модель по умолчанию `claude-opus-5-5`, ключ `ANTHROPIC_API_KEY`.
  Работает через официальный SDK `anthropic` (`pip install -r requirements.txt`).
- **Заглушка** — пресет «Заглушка (без сети)» (`base_url = stub://local`): ключ и интернет не нужны, ИИ-ответ собирается из правил с пометкой «[Заглушка ИИ]». Годится для демо, пока реальный API не выбран.
- **Российские:** пресеты **YandexGPT** (OpenAI-совместимый эндпоинт Yandex Cloud, модель `gpt://<ID каталога>/yandexgpt/latest`) и
  **GigaChat** (ключ обменивается на токен автоматически; нужен сертификат Минцифры — `CC_AI_CA_BUNDLE`). См. `.env.example`.
- **OpenAI-совместимый** (`/chat/completions`): OpenAI, OpenRouter, Groq, локальные Ollama / vLLM / LM Studio.
Кнопки: быстрые пресеты провайдеров, «Список моделей» (`GET /models`), «Проверить подключение».

Ключ лучше не вводить в интерфейсе, а положить в файл `.env` (в `.gitignore`):

```bash
cp .env.example .env     # и заполнить ANTHROPIC_API_KEY (или CC_AI_API_KEY), при необходимости CC_AI_BASE_URL / CC_AI_MODEL
```

Модель получает JSON-снимок сделки (температура, загрузка, наработка, совпадение серийных номеров, связь, покрытие) и возвращает
риск, замечания и рекомендации. Правила работают всегда (без ИИ и при его сбое), а ИИ не может занизить риск, найденный жёсткими
правилами. Ключ хранится на сервере и в интерфейс не возвращается.

## Почта

Письма заёмщику и в ЦОД, ссылки восстановления пароля и e-mail-уведомления пишутся в журнал (`data/db.json → outbox`).
Чтобы письма уходили реально, задайте `CC_SMTP_HOST` (+ `CC_SMTP_PORT`, `CC_SMTP_USER`, `CC_SMTP_PASSWORD`, `CC_SMTP_FROM`) в `.env`.

## Агент на серверах

```bash
python agent/agent.py --server http://HOST:8765 --key CC-7F2K-91QX --name srv-01      # ключ — из шага «Телеметрия»
python agent/agent.py ... --mock                                                       # проверка без GPU
```

Раз в 5 минут шлёт серийные номера, температуру, загрузку и наработку (счётчик ведёт сам агент). Сервер сверяет серийные номера
с договором, считает молчащий сервер (больше часа — поправка −7 %, больше суток — уведомление) и замечает сброс счётчика наработки.

## Демо в браузере без установки

`python demo/build.py` собирает `demo/dist/index.html` — один файл, где «сервер» (расчёты, роли, уведомления, письма) работает
прямо в браузере. Логика демо дублирует серверную (`demo/demo.js`); при правках `engine.py`, `alerts.py`, `server.py` её нужно синхронизировать.
В демо файлы не скачиваются, а открываются в окне; внешние API (ИИ, SMTP) отключены; Excel заменён на CSV.

## Ограничения

* Рыночные цены, ставки аренды и сценарии падения — **демонстрационные допущения**, не реальные данные. Их нужно заменить подключением
  к прайсам дилеров и ценам вторичного рынка (`market.py`). Ежедневное обновление цен в демо — имитация.
* Модель износа (наработка, температура, загрузка) эвристическая, её нужно калибровать на реальных сделках.
* Роли и учётные записи в ТЗ выдаёт корпоративная система доступа; здесь — пять демо-пользователей и вход по паролю.
* Хранилище — JSON-файл, сессии в памяти: для настольного приложения и хакатона, не для промышленной эксплуатации.
  Сервер слушает только `127.0.0.1`; при выставлении наружу нужны TLS и полноценная аутентификация.
