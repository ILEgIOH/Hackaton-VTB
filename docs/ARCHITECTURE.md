# Архитектура, автоматизация и масштабирование

## Компоненты

```
 Серверы заёмщика (ЦОД)                    Контур банка
 ┌──────────────────────┐   HTTPS + HMAC   ┌───────────────────────────────────────────────┐
 │ agent.py             │ ───────────────▶ │ ComputeCollateral (run.py)                    │
 │ nvidia-smi → 4 поля  │  раз в 1–5 мин   │  ├─ API + интерфейс (server.py)               │
 │ (только stdlib)      │                  │  ├─ движок оценки (engine.py, ≈0,1 мс)        │
 └──────────────────────┘                  │  ├─ правила уведомлений (alerts.py)           │
                                           │  ├─ планировщик (monitor.py): переоценка 590-П, │
 Аналитик, риски, залоговая служба,        │  │   цены рынка, срок хранения, ИИ-анализ      │
 ВТБ Лизинг ── браузер ──────────────────▶ │  ├─ состояние: db.json (отложенная запись)    │
                                           │  └─ журнал + телеметрия: SQLite (WAL)          │
                                           └──────┬──────────────┬──────────────┬──────────┘
                                                  │              │              │
                                     LLM в контуре или      SMTP банка    Prometheus / SIEM
                                     GigaChat                             (/api/metrics, /api/audit)
```

## Что автоматизировано

| Процесс | Было (вручную) | В сервисе |
|---|---|---|
| Оценка залога | оценщик, 5–15 рабочих дней | три метода и прогноз на срок кредита, ≈5 с с учётом интерфейса |
| Подбор безопасной суммы | экспертно | рекомендуемый LTV: долг в пессимистичном сценарии не выше залога ни в одном месяце |
| Квартальная переоценка (590-П) | заявка оценщику | планировщик, раз в 90 дней (настраивается), прежняя оценка — в документах |
| Контроль наличия залога | выездные проверки | агент сверяет серийные номера каждого пакета |
| Сигналы о рисках | нет | подмена, перегрев, потеря связи, ковенант, прогноз разрыва — уведомление нужному отделу |
| Заключение для кредитного комитета | вручную | PDF или Word в один клик |
| Журнал для аудита | разрозненно | автоматически, с проверкой целостности |

## Замеры (воспроизводятся: `python tools/bench.py`)

MacBook (Apple Silicon), Python 3.12, один процесс, 8 потоков-агентов, подписанные пакеты по 8 карт:

| Показатель | Значение |
|---|---|
| Полный расчёт оценки, 32 GPU | 0,10 мс |
| Полный расчёт оценки, 512 GPU | 0,40 мс |
| От пакета агента до уведомления о подмене | < 1 мс (медиана) |
| Приём телеметрии, запись состояния на каждый пакет | ≈ 550 пакетов/с |
| Приём телеметрии, отложенная запись (Спринт 2) | ≈ 1 450 пакетов/с, ускорение ×2,7 |
| Ёмкость одного экземпляра при отправке раз в минуту | ≈ 87 тыс. серверов заёмщиков |
| То же при отправке раз в 5 минут (по ТЗ) | ≈ 435 тыс. серверов |

Для сравнения: в пилоте 2–3 сделки, это десятки серверов. Запас по нагрузке — три-четыре порядка.

## Путь к промышленной нагрузке

1. **Хранилище.** Состояние переходит из `db.json` в PostgreSQL или Postgres Pro. Таблицы журнала и телеметрии
   (`journal.py`) переносятся без изменения API. Телеметрию можно разбить на секции по месяцам.
2. **Горизонтальное масштабирование.** Несколько экземпляров API за балансировщиком банка. Приём телеметрии
   отделяется в свой процесс (очередь, например Kafka банка). Планировщик работает в одном экземпляре с блокировкой в БД.
3. **Надёжность.** `/api/health` для оркестратора, `/api/metrics` для Prometheus и Grafana. Состояние записывается
   атомарно (через временный файл), а при остановке сбрасывается на диск. Журнал SQLite работает в режиме WAL.
4. **Агент без установки.** Для серверов, куда нельзя ставить ПО, — опрос BMC по Redfish (серийные номера и температуры
   доступны без агента). Это следующий шаг после пилота.
5. **ИИ.** Локальная модель через vLLM на одном GPU банка. Нагрузка небольшая: один анализ на сделку раз в 30 минут.

## Развёртывание

```bash
docker build -f deploy/Dockerfile.onprem -t computecollateral .
docker compose -f deploy/docker-compose.yml up -d                  # сервис
docker compose -f deploy/docker-compose.yml --profile llm up -d    # + локальная модель ИИ
```

Без Docker: `python run.py --no-window --host 0.0.0.0`. Нужен только Python 3.10+, остальные зависимости необязательны.
