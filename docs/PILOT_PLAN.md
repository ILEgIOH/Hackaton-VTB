# План пилота и внедрения

**Цель пилота.** За 12 недель на 2–3 реальных сделках с ЦОД проверить, что сервис даёт оценку залога сопоставимо
с оценщиком, сокращает время до решения и находит события с залогом раньше квартальной проверки.

## Что нужно от банка

| Ресурс | Объём |
|---|---|
| Ментор из залоговой службы или управления рисков | 2 часа в неделю |
| Методолог по 590-П и оценке залогов | 3–4 встречи |
| ИБ: согласование развёртывания | 1 виртуальная машина в тестовом контуре (4 vCPU, 8 ГБ, 50 ГБ), доступ агентов по HTTPS |
| 2–3 клиента-ЦОД | согласие поставить агента (4 показателя карт, код открыт) |
| Отчёты оценщика по этим сделкам | для сравнения точности |

## График

| Недели | Этап | Результат |
|---|---|---|
| 1–2 | Развёртывание в тестовом контуре (Docker, `CC_ONPREM=1`), вход через SSO, TLS | сервис доступен сотрудникам пилота |
| 2–3 | Методология: веса методов, дисконты, сценарии, пороги — сверка с методологами | протокол настроек |
| 3–4 | Подключение агентов у 2–3 заёмщиков, сверка серийных номеров с договором | телеметрия по всем серверам |
| 4–10 | Параллельная работа: оценки сервиса рядом с процессом банка, разбор уведомлений | журнал событий и решений |
| 6 | Промежуточный отчёт: точность против оценщика, ложные срабатывания | корректировка порогов |
| 10–12 | Итоговый отчёт, решение о внедрении | отчёт по критериям ниже |

## Критерии успеха

| Метрика | Цель | Как измеряем |
|---|---|---|
| Время до оценки залога | ≤ 1 рабочего дня вместо 5–15 | журнал аудита: от создания сделки до готовой оценки |
| Отклонение от отчёта оценщика | ≤ 15 % | сравнение по каждой сделке пилота |
| Время от события до уведомления | ≤ 5 минут | телеметрия + журнал уведомлений |
| Доля сделок с телеметрией | ≥ 50 % | статус агента |
| Ложные тревоги о подмене | 0 | разбор залоговой службой |
| Оценка сотрудников | ≥ 4 из 5 | опрос участников пилота |

## Риски пилота

| Риск | Что делаем |
|---|---|
| Заёмщик не разрешает агента | работаем по рыночной переоценке; агент — условие кредита со сниженной ставкой |
| Мало рыночных цен на б/у GPU в РФ | пометка «мало данных» и смещение весов к затратному методу (уже в движке); подключение прайсов дилеров |
| ИБ не согласует внешний ИИ | локальная модель в контуре (профиль `llm`) или работа без ИИ — расчёты от него не зависят |
| Расхождение с методикой банка | все коэффициенты вынесены в настройки и согласуются на неделях 2–3 |

## После пилота

1. Интеграция с кредитным конвейером (API `whatif` и `export`) и единым входом.
2. ИИ-модель внутри контура банка.
3. ВТБ Лизинг: прогноз остаточной стоимости GPU-оборудования в лизинге.
4. Залог серверов целиком: CPU, память, сеть; опрос BMC по Redfish без агента.
5. PostgreSQL и горизонтальное масштабирование ([ARCHITECTURE.md](ARCHITECTURE.md)).
