# Данные, безопасность и комплаенс

Документ показывает, как ComputeCollateral выполняет условия хакатона и что остаётся сделать в пилоте.
Полное соответствие банковским нормативам на этапе соревнования не требуется. Мы показываем, что его можно
обеспечить в контуре ВТБ, и где в коде это уже реализовано.

## 1. Какие данные обрабатываются

| Данные | Чьи | Категория | Где хранятся | Срок |
|---|---|---|---|---|
| ФИО, рабочая почта, роль, хэш пароля | сотрудники банка | персональные данные (152-ФЗ) | `data/db.json` в контуре | пока действует учётная запись |
| Название, ИНН, номер заявки | заёмщик-юрлицо | банковская тайна; ИНН ИП — персональные данные | `data/db.json` | срок кредита + архив банка |
| ФИО и почта контакта в ЦОД | представитель заёмщика | персональные данные | `data/db.json` | срок кредита |
| Серийные номера, температура, загрузка, наработка GPU | оборудование | не ПДн, коммерческая информация | `data/journal.sqlite` (история) | `CC_TELEMETRY_DAYS`, по умолчанию 400 дней |
| Журнал действий | сотрудники | ПДн сотрудников (почта, IP) | `data/journal.sqlite` | по регламенту банка |

Агент на серверах заёмщика собирает только 4 показателя видеокарт. Он не читает файлы, процессы и сетевой трафик
клиента ([agent/agent.py](../agent/agent.py)).

## 2. Соответствие условиям хакатона

| Условие | Как выполнено | Где в коде | Статус |
|---|---|---|---|
| Работа on-prem в контуре с ограничением доступа к открытой сети | Режим `CC_ONPREM=1`: обращения к ИИ и почте разрешены только на внутренние адреса (loopback, 10/8, 172.16/12, 192.168/16) и хосты из `CC_ALLOWED_HOSTS`. Внешних CDN и шрифтов нет, интерфейс полностью локальный | `security.check_egress`, `ai.chat`, `mailer.send` | сделано, есть тесты |
| Генеративный ИИ на российских и/или on-prem моделях | Подключение по OpenAI-совместимому API: GigaChat (Сбер) или локальная модель (vLLM, Ollama) в контуре. В `deploy/docker-compose.yml` есть профиль `llm` с локальной моделью | `ai.py`, `deploy/docker-compose.yml` | сделано |
| ИИ не влияет на решения | Стоимость, LTV, статусы и уведомления считаются детерминированными правилами. Замечания правил показываются всегда: модель не может их убрать, переписать или понизить риск. Её находки выводятся отдельным блоком «Дополнительно от ИИ» | `ai.analyze` | сделано, есть тесты |
| Маскирование данных перед нейросетью | Снимок сделки обезличивается структурно. Свободный текст (замечания правил, вопросы сотрудника в чате) маскируется: название, ИНН, договор, контакт, почта и локация заёмщика заменяются метками, серийные номера — псевдонимами; шаблонами вырезаются почты, телефоны, номера карт, СНИЛС, паспорта, счета и ИНН. В ответе модели реквизиты сделки восстанавливаются для сотрудника. Сколько и чего скрыто, пишется в журнал аудита; сами значения не пишутся | `security.mask_text`, `security.unmask_text`, `ai.ask_ex` | сделано, есть тесты |
| 152-ФЗ: минимизация, защита, локализация | Данные хранятся только в контуре банка (локализация, ст. 18 ч. 5). Для ИИ данные обезличиваются: нет названия заёмщика и номера договора, серийные номера заменены псевдонимами. История хранится ограниченный срок, доступ разграничен по ролям | `security.deidentify_snapshot`, `journal.purge_telemetry`, `users.PERMS` | сделано, есть тесты |
| 115-ФЗ | Проверка ИНН по перечню на шаге «Заёмщик». При совпадении сделка останавливается до проверки комплаенсом, событие пишется в журнал. Перечень загружает банк (`CC_STOPLIST`) | `security.aml_check`, `/api/check-inn`, `/api/deals` | прототип; в пилоте — интеграция с AML-системой банка |
| Требования ИБ | Только домен банка; 3 ошибки входа → блокировка на 15 минут; сессия 30 минут; PBKDF2-SHA256 (120 000 итераций); права проверяются на сервере; cookie `HttpOnly` и `SameSite=Strict` (`Secure` за TLS); CSP, `X-Frame-Options`, `nosniff`, проверка Origin (CSRF) | `server.py`, `store.py` | сделано, есть тесты |
| Неизменяемый журнал действий | Каждое изменяющее действие, вход, отказ в доступе и выгрузка пишутся в журнал. Записи связаны цепочкой SHA-256, поэтому правка задним числом обнаруживается кнопкой «Проверить целостность» | `journal.py`, экран «Безопасность и аудит» | сделано, есть тесты |
| Подлинность данных с серверов заёмщика | Пакеты агента подписываются HMAC-SHA256. Сам ключ по сети не передаётся. Действует окно ±5 минут и защита от повтора; отклонённые пакеты пишутся в журнал | `security.verify_signature`, `agent/agent.py` | сделано, есть тесты |
| 590-П: переоценка залога не реже раза в квартал | Планировщик переоценивает сделки, оценка которых старше 90 дней. Прежняя оценка сохраняется в документах, автору приходит уведомление | `App.auto_revalue`, `monitor.py` | сделано, есть тесты |
| Предпочтение российскому ПО, open-source | Python и стандартная библиотека; SQLite, в пилоте — PostgreSQL или Postgres Pro. Можно собрать образ на Astra Linux, РЕД ОС или ALT. Зарубежных SaaS нет | `Dockerfile`, `requirements.txt` | сделано |
| Масштабирование и надёжная работа | Отложенная запись состояния, история в SQLite (WAL), health-check и метрики Prometheus, Docker. План перехода на PostgreSQL и несколько экземпляров — в [ARCHITECTURE.md](ARCHITECTURE.md) | `store.py`, `/api/health`, `/api/metrics` | сделано, замеры в `tools/bench.py` |
| Интеграция с системами банка | REST API и описание OpenAPI для кредитного конвейера, единого входа и AML | [openapi.yaml](openapi.yaml) | описано; интеграция — в пилоте |

## 3. Модель угроз (кратко)

| Угроза | Мера |
|---|---|
| Подмена видеокарты в ЦОДе | сверка серийных номеров каждого пакета с договором залога, уведомление залоговой службе |
| Поддельные данные от «агента» | HMAC-подпись, окно по времени, защита от повтора, журнал отказов |
| Агент отключён, чтобы скрыть вывод залога | правило «нет связи»: предупреждение через 1 ч, уведомление через 24 ч (пороги настраиваются) |
| Утечка данных клиента через ИИ | обезличивание снимка и маскирование свободного текста; в контуре — только внутренняя модель |
| Подбор пароля | блокировка после 3 ошибок, одинаковый ответ на восстановление пароля для любой почты |
| Сотрудник правит историю решений | журнал с цепочкой хэшей; запись только дописывается |
| Межсайтовые запросы | `SameSite=Strict`, проверка Origin, CSP, `frame-ancestors 'none'` |

## 4. Что сделать в пилоте вместе с банком

1. Вход через корпоративную систему банка (SSO, LDAP или Kerberos) вместо собственных паролей.
2. TLS на балансировщике банка (`CC_HTTPS=1`). Агенты обращаются к сервису по `https://`.
3. Интеграция с AML-системой банка вместо файла `stoplist.csv`.
4. PostgreSQL или Postgres Pro и резервное копирование по регламенту банка.
5. Передача журнала аудита в SIEM банка (формат JSON, `/api/audit`).
6. Согласование с ИБ: модель нарушителя, оценка соответствия ГОСТ Р 57580.1 по требованиям банка, при необходимости — анализ уязвимостей.
7. Регламент обработки ПДн: уведомление контактных лиц ЦОД, сроки хранения, ответственные.
